# 业务需求与规则

## 1. 业务目标

本工具用于管理 ITK China 的电脑资产，覆盖以下核心场景：

- 维护电脑基础信息
- 维护人员基础信息
- 维护库存电脑
- 跟踪电脑归属变化
- 支持邮件盘点
- 支持后续内网化和多人协作演进

## 2. 核心对象

### 电脑

字段包括：

- 电脑名称
- 序列号
- 固定资产号
- 型号
- MAC 地址
- 归属人
- 备注
- 更新时间
- 归属历史

规则：

- 序列号必填
- 固定资产号可以为空
- MAC 地址可以为空
- 固定资产号 / MAC 空值统一展示为 `N/A`
- 归属人为空表示库存
- 编辑已有电脑需要授权密码 `1`

### 人员

字段包括：

- 中文名
- 拼音
- 邮箱
- 部门
- 员工类型
- Mentor

规则：

- 员工类型分为正式员工 / 实习生
- 实习生必须关联一位正式员工 Mentor
- 正式员工不需要 Mentor
- 删除被实习生引用为 Mentor 的人员时必须阻止

## 3. 功能需求

### 电脑管理

必须支持：

- 新增电脑
- 编辑电脑
- 搜索电脑
- 查看归属历史
- 将电脑转入库存

### 库存管理

必须支持：

- 查看库存电脑
- 新增库存电脑
- 编辑库存电脑
- 删除库存电脑
- 将库存电脑分配给指定人员

### 人员管理

必须支持：

- 新增人员
- 编辑人员
- 删除人员
- 搜索人员
- 维护 Mentor 关系

删除人员时：

- 如果仍被作为 Mentor 引用，则禁止删除
- 如果允许删除，其名下电脑自动转入库存

### 邮件盘点

当前规则：

- 点击邮件盘点后先展示待发送对象列表
- 支持勾选、全选、取消全选
- 正式员工名下电脑发给本人
- 实习生名下电脑发给对应 Mentor
- 同一个 Mentor 的相关电脑应合并到同一封邮件
- 对没有邮箱、没有 Mentor 等情况给出跳过原因
- 生成邮件草稿后写入盘点批次记录

### 云端备份

当前桌面版规则：

- 数据可上传到个人 NAS File Browser 指定目录
- 数据可从云端拉回本地
- 拉取会覆盖本地 JSON
- 启动时只提醒云端有新版本，不自动覆盖
- 上传前要检查云端版本，避免旧版本覆盖新版本

## 4. 多人协作需求

当前桌面版和 Web 版都仍基于 JSON 文件存储，因此多人同时写入存在风险。

目标问题：

- 避免多人同时使用时旧数据覆盖新数据
- 避免长时间打开后提交编辑，覆盖他人刚更新的数据

后续正式 Web 版建议：

- 使用统一数据库作为事实源
- 用登录和权限替代本地密码机制
- 对编辑操作增加记录级冲突检测

## 5. Web 端现状与后续需求

### 当前已实现

- 首页仪表盘
- 列表、搜索、详情
- 电脑 / 人员 / 库存 CRUD
- 邮件盘点
- 列表排序与若干展示优化

### 后续正式版需求

- 账号登录
- 角色权限
- 数据库替代 JSON
- 多人同时访问
- 更稳的部署与运维方式

## 6. 当前已知限制

- Web 端与桌面版共享 JSON 文件，不适合多人同时写入
- Web 端尚未实现登录和角色控制
- 当前没有数据库
- 历史数据与部分旧字符串存在编码清理成本

## 7. 验收优先级

当前最重要的验收顺序建议为：

1. 数据正确读写
2. 核心业务规则不丢失
3. Web 与桌面版规则一致
4. 页面交互清晰可用
5. 再继续推进数据库、权限和并发控制
