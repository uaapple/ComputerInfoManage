# 业务需求与规则

## 1. 业务目标

本工具用于管理 ITK China 的电脑资产，覆盖以下核心场景：

- 维护电脑基础信息
- 维护人员基础信息
- 维护库存电脑
- 跟踪电脑归属变化
- 支持盘点和导出
- 支持后续内网化和多人协作

## 2. 核心对象

### 电脑

字段包括：

- 电脑名称
- 序列号
- 固定资产号
- 型号
- MAC 地址
- 归属人
- 备注
- 更新时间
- 归属历史

规则：

- 序列号必填
- 固定资产号可为空，可选“暂无”
- MAC 地址可为空，可选“暂无”
- 固定资产号 / MAC 空值统一展示为 `N/A`
- 归属人为空表示库存

### 人员

字段包括：

- 中文名
- 拼音
- 邮箱
- 部门
- 员工类型
- Mentor

规则：

- 员工类型分为正式员工 / 实习生
- 实习生必须关联一位正式员工 Mentor
- 正式员工不需要 Mentor
- 删除被实习生引用为 Mentor 的人员时必须阻止

## 3. 功能需求

### 电脑管理

必须支持：

- 新增电脑
- 编辑电脑
- 搜索电脑
- 导出电脑 CSV
- 查看归属历史
- 将电脑转入库存

### 库存管理

必须支持：

- 查看库存电脑
- 新增库存电脑
- 编辑库存电脑
- 删除库存电脑
- 将库存电脑分配给指定人员

### 人员管理

必须支持：

- 新增人员
- 编辑人员
- 删除人员
- 搜索人员
- 维护 Mentor 关系

### 邮件盘点

当前桌面版规则：

- 点击邮件盘点后先弹收件人列表
- 支持勾选、全选、取消全选
- 正式员工名下电脑发给本人
- 实习生名下电脑发给对应 Mentor
- 同一个 Mentor 的多台相关电脑应合并到同一封邮件

### 云端备份

当前桌面版规则：

- 数据可上传到个人 NAS File Browser 指定目录
- 数据可从云端拉回本地
- 拉取会覆盖本地 JSON
- 启动时只提醒云端有新版本，不自动覆盖
- 上传前要检查云端版本，避免旧版本覆盖新版本

## 4. 多人协作需求

原始桌面版是单机工具，但当前需求已经明确包含多人协作场景。

目标问题：

- 避免多人同时使用时，旧数据覆盖新数据
- 避免打开工具后长时间编辑，提交时覆盖他人刚更新的数据

当前桌面版采取的临时策略：

- 云端版本检查
- 提醒先拉取再编辑

后续正式 Web 版的目标策略：

- 使用统一数据库作为事实源
- 用登录和权限替代本地密码机制
- 对编辑操作增加记录级冲突检测

## 5. Web 版需求

### 第一阶段目标

Web 版第一阶段目标是：先把当前桌面版的核心查询和首页工作台视觉做出来，并逐步演进为正式系统。

当前已明确的 Web 版要求：

- 视觉风格：企业清新蓝白
- 顶部品牌区：包含 ITK Logo、标题、副标题
- 首页结构：仪表盘 + 列表
- 列表视图：在用电脑 / 库存电脑 / 人员名单
- 搜索栏必须清晰、不和按钮遮挡
- 详情优先用弹窗或抽屉

### 后续正式版要求

- 账号登录
- 角色权限
- 内网部署到 Windows 虚拟机 `10.36.76.95`
- 多人同时访问
- 数据库替代 JSON
- 支持编辑和维护

## 6. 当前已知实现偏差

这些点在接手开发时需要优先注意：

- README 里曾有旧密码描述，实际当前密码是 `1`
- Web 预览版服务端存在中文编码脏数据
- Web 预览版当前只能读数据，不能写数据
- Web 预览版尚未实现登录和角色控制
- Web 预览版与桌面版暂时并存，但不能视为两个都适合多人写入

## 7. 验收优先级

当前最重要的验收顺序建议为：

1. 数据正确读取
2. 核心业务规则不丢失
3. 多人协作风险可控
4. 页面视觉清爽、品牌一致
5. 再继续做高级功能
